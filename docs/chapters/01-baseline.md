# 1장. 기준선: 그냥 RAG

흔히 하는 방식 그대로 만든다. 법령 본문을 일정한 길이로 자르고, 임베딩해서, 질문과 코사인 유사도가 높은 조각을 가져온다. 이 장의 숫자가 이후 모든 장의 출발점이다.

## 설정

| 항목 | 값 |
|---|---|
| 대상 | 법률 4개 + 시행령 4개, **현행 조문만** 1,548개(별표 포함), 스냅샷 `20261120T144052-a0fb33dd` |
| 청킹(C0) | 문서마다 조문을 이어 붙이고 조 경계를 무시한 채 500토큰씩 자름(겹침 50, bge-m3 토크나이저 기준). 조각 1,611개, 조각 하나에 평균 조문 2.05개 |
| 임베딩(D1) | `BAAI/bge-m3` 단일 벡터(1024차원, 정규화), 맥 M4 MPS. 색인 만드는 데 207초 |
| 검색 | pgvector 코사인 거리로 상위 20조각, 전수 비교 |

| 커밋 | `c0401b8` |

채점은 조문 단위다. 조각 하나에 조문이 여러 개 걸치면 조각 안 순서대로 모두 결과로 치고, 같은 조문은 처음 나온 순위만 남긴다. 규칙은 `src/proviso/eval/metrics.py` 머리말 참고.

## 관찰

1. **시점 문항은 0점이다.** 색인에 현행 조문만 넣었으니 당연하다. 2019년 기준을 물어도 지금 조문만 돌려준다. 이 숫자는 7장(연혁·기준일)의 출발점이다. 시점 문항을 빼고 보면 recall@10은 0.632다.
2. **위임 문항이 약하다(0.400).** 시행령은 "법 제N조제M항에서 대통령령으로 정하는 ~란"으로 시작해서, 질문에 담긴 일반인 말과 표현이 멀다. 시행령 전체가 법률보다 낮게 나오는 것과 같은 원인으로 보인다.
3. **짧은 키워드 질문과 오타 질문이 약하다.** 차이 구간은 겹치지만 방향은 일관된다. 키워드 검색(BM25)과 섞으면 나아질지가 3장의 질문이다.
4. **법령 이름이 있으면 조금 낫다(0.638 vs 0.546).** 약칭을 정식 이름으로 펼치는 방법(Q3)을 시도할 이유가 된다.
5. **예상과 달리, 조각 경계에 잘린 조문이 더 못 찾히지는 않았다.** 정답 조문이 여러 조각에 걸쳐 잘린 문항의 recall@10은 0.669, 한 조각에 통째로 들어간 문항은 0.564였다(시점 문항 제외). 긴 조문은 여러 조각에 나뉘어 들어가서 걸릴 기회가 오히려 많다. 짧은 조문은 앞뒤 다른 조문과 한 조각에 섞여 묻힌다. 그래서 2장의 문제는 "잘려서"보다 "**섞여서** 못 찾는다"에 가깝다. 조 단위 청킹이 짧은 조문을 살리는지, 긴 조문에서는 손해를 보는지 함께 잰다.

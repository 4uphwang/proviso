# 3장. 단어가 맞는데도 못 찾는다: 키워드 검색과 결합

## 문제

2장까지는 벡터 검색만 썼다. 벡터 검색은 뜻이 비슷한 문장을 잘 찾지만, **질문에 조문과 똑같은 단어가 있어도 그 단어를 꼭 맞히지는 않는다.** 2장 결과에서 보인 약점은 이렇다.

- 키워드형 질문(0.737)이 완결 문장(0.823)보다 낮다. 짧은 질문은 문장 뜻보다 단어 몇 개가 전부다.
- 위임 문항에서 법과 시행령을 둘 다 찾는 비율이 0.600이다. 시행령 조문은 "법 제N조제M항에서 대통령령으로 정하는"처럼 용어와 조 번호로 이어진다.
- 질문에 "자본시장법", "금소법" 같은 약칭을 써도, 조문과 머리말에는 정식 명칭("자본시장과 금융투자업에 관한 법률")만 있다.

## 처방 세 가지 (한 번에 하나씩)

| | 처방 | 내용 |
|---|---|---|
| B1 | 형태소 BM25 | kiwipiepy로 형태소를 나누고, 조사·어미를 뺀 내용어(명사, 동사 어간, 숫자 등)로 BM25 색인을 만든다. "제23조의2" 같은 조 번호는 통째로도 넣는다. 조문 하나가 문서 하나이고, 2장의 머리말(법령명 > 장 > 조 제목)을 함께 넣는다 |
| F1 | RRF 결합 | 벡터(2장 C3+C1)와 BM25가 각각 서로 다른 조문 100개를 내면, 순위만 써서 점수 = Σ 1/(60 + 순위)로 합친다. 두 검색의 점수 크기를 맞출 필요가 없다 |
| Q3 | 약칭 확장 | 질문에 약칭이 있으면 정식 법령명을 질문 뒤에 붙인다. "금소법 시행령"처럼 법률 약칭 뒤에 시행령이 오면 시행령 정식 명칭을 붙인다. 약칭 목록은 법령 API의 약칭과 `sources.yaml`의 수동 별칭이다 |

키워드 검색은 dev에서 후보 셋을 견줘 하나를 골랐다.

| dev recall@10 | 값 |
|---|---:|
| 형태소 BM25, 머리말 없이 | 0.720 |
| **형태소 BM25, 머리말 포함(B1)** | **0.750** |
| 글자 2-gram BM25, 머리말 포함(B3) | 0.740 |

형태소 BM25를 골랐다(B3과는 차이가 작다). 머리말을 함께 넣는 것은 계획서의 B2(법령명·조 제목 가중)를 대신한다. 학습형 희소 검색(B4, bge-m3 sparse)은 다른 라이브러리가 필요해서 이번 장에서는 하지 않았다.

## 결과 (test 700문항)

| 지표 | 2장(벡터) | BM25 단독 | + RRF 결합 | + 약칭 확장 |
|---|---:|---:|---:|---:|
| recall@1 | 0.441 | 0.339 | 0.426 | **0.443** |
| recall@5 | 0.703 | 0.626 | 0.727 | **0.737** |
| recall@10 | 0.764 | 0.707 | 0.791 | **0.803** |
| recall@20 | 0.811 | 0.777 | 0.841 | **0.854** |
| MRR@10 | 0.556 | 0.466 | 0.554 | **0.570** |
| 위임: 법·시행령 둘 다 @10 | 0.600 | | 0.743 | **0.771** |
| 검색 지연 p50 | 49 ms | 0.6 ms | 50 ms | 51 ms |

짝지은 부트스트랩(95%)으로 본 차이:

| 비교 | recall@10 | MRR@10 | 상위 10 안으로 / 밖으로 |
|---|---|---|---|
| 2장 → RRF | +0.027 [+0.003, +0.050] | −0.002 [−0.025, +0.020] | 46 / 27 |
| RRF → + 약칭 | +0.011 [+0.001, +0.021] | +0.015 [+0.006, +0.025] | 11 / 3 |
| 2장 → 최종 | +0.039 [+0.014, +0.063] | +0.013 [−0.011, +0.038] | 51 / 24 |
| 1장 기준선 → 최종 | +0.230 [+0.196, +0.266] | +0.276 [+0.242, +0.307] | 183 / 22 |

dev 300문항도 같은 방향이다(recall@10 0.757 → 0.797 → 0.803).

**RRF 결합은 정답을 상위 10 안으로 더 많이 넣지만, 1위는 늘리지 못했다.** recall@10과 @20은 확실히 올랐고, recall@1과 MRR은 그대로다. 벡터가 1위로 올린 정답 중 65개가 결합 뒤 2~4위로 밀렸고, 54개는 새로 1위가 됐다. 순위만 보고 합치면, 벡터는 확신하는데 BM25가 낮게 본 정답이 손해를 본다. 순위를 다듬는 일은 4장(재정렬)의 질문이다.

### 두 검색은 서로 다른 문항을 맞힌다 (시점 문항 제외 635문항, 상위 10 기준)

| | 문항 수 | RRF 결합 뒤 상위 10 안 |
|---|---:|---:|
| 둘 다 찾음 | 449 | 449 |
| 벡터만 찾음 | 86 | 59 |
| BM25만 찾음 | 46 | 35 |
| 둘 다 못 찾음 | 54 | 11 |

BM25 단독은 벡터보다 낮지만, 벡터가 놓친 46문항을 찾는다. 둘 중 하나라도 찾은 비율은 0.915이고, 결합(약칭 확장 전)은 0.872까지 따라갔다. 벡터만 찾던 27문항과 BM25만 찾던 11문항을 결합 뒤 놓쳤고, 둘 다 못 찾던 11문항은 새로 찾았다.

### 어디서 좋아졌나 (recall@10, 2장 → 최종)

| 구분 | n | 2장 | 최종 | 차이 95% 구간 |
|---|---:|---:|---:|---|
| 키워드형 | 213 | 0.737 | 0.793 | [+0.009, +0.103] |
| 짧은 구어 | 250 | 0.732 | 0.760 | [−0.012, +0.072] |
| 완결 문장 | 237 | 0.823 | 0.857 | [+0.004, +0.068] |
| 위임 따라가기 | 70 | 0.686 | 0.829 | [+0.057, +0.243] |
| 별표 | 35 | 0.743 | 0.886 | [−0.029, +0.314] |
| 오타 있음 | 40 | 0.675 | 0.725 | (n이 작다) |

- **위임 문항이 가장 많이 올랐다.** 시행령은 법과 같은 용어("대통령령으로 정하는 ~")를 그대로 쓴다. 단어를 맞추는 검색이 법과 시행령을 함께 끌어온다. 시행령 전반도 올랐다(예: 자본시장법 시행령 0.751 → 0.862).
- **2장에서 떨어진 별표가 대부분 돌아왔다**(0.743 → 0.886). 별표 본문에는 "채권평가회사", "업무정지" 같은 단어가 그대로 있다. 별표만 따로 손대지 않고 다시 올라왔다.
- **질문과 조문의 단어가 거의 겹치지 않는 문항은 오히려 조금 내려갔다**(겹침 0.3 미만, 0.683 → 0.655). 키워드 검색은 같은 단어가 있어야 돕는다. 일반인 말을 법률 용어로 바꾸는 일이 4장의 질문이다.

### 약칭 확장

약칭을 펼치니 법령명을 쓴 질문(207문항)에서 recall@10이 0.807 → 0.845로 올랐고, 법령명이 없는 질문은 그대로였다(바뀌는 질문이 없으니 당연하다). dev에서 법령명을 쓴 질문의 BM25 상위 5개 중 같은 법(법률 + 시행령) 조문 비율은 0.72 → 0.85가 됐다.

다만 **벡터 검색 단독에 약칭을 펼치면 조금 나빠진다**(test MRR −0.011 [−0.021, −0.001], dev는 차이 불분명). 짧은 질문 뒤에 긴 정식 명칭이 붙으면 질문 임베딩이 법령 이름 쪽으로 쏠리는 것으로 보인다. 지금은 결합 전체에 한 번 적용했고, BM25 쪽에만 적용하는 것은 이후 장에서 dev로 확인할 후보로 남긴다.

## 결과대로 기록한 것

- dev에서는 형태소 BM25(0.750)가 글자 2-gram(0.740)보다 조금 나아 골랐지만, test에서는 거꾸로였다(0.707 vs 0.720, 차이 불분명). 고른 것은 바꾸지 않는다.
- dev와 test 모두에서 BM25 단독이 벡터 단독보다 낮다(test 0.707 vs 0.764). dev에서는 거의 같았다(0.750 vs 0.757).

## CI 점수 검사

GitHub Actions에서 검색 점수가 떨어지면 실패하게 했다. bge-m3는 CI에서 매번 받기에 무거워서(약 2GB), **모델이 필요 없는 형태소 BM25 + 약칭 확장**으로 잰다.

- 말뭉치: 현행 조문 1,548개를 압축해 `tests/fixtures/corpus.jsonl.gz`(약 600KB)로 넣었다. 법령 본문은 저작권법 제7조의 보호받지 못하는 저작물이고, 출처(법제처 국가법령정보센터)를 파일 첫 줄에 적었다. 그래서 CI에 DB를 채울 필요가 없다.
- 문항: 시점 문항을 뺀 905문항(dev + test). 설정을 고르는 데 쓰지 않는 회귀 검사라서 test를 넣어도 된다.
- 기준: `evalset/ci_gate.json`의 recall@10 0.8066에서 허용폭 0.01을 뺀 값 아래면 실패. 9초 걸린다.
- 비밀값 검사(`tests/test_no_secrets.py`)가 압축 파일도 풀어서 본다.

## 남은 문제

- **1위가 늘지 않았다**(recall@1 0.441 → 0.443). 상위 10 안에는 들지만 맨 위로 올리지 못한다. 에이전트가 앞 몇 개만 읽는다면 이 숫자가 중요하다.
- **단어가 겹치지 않는 질문**(겹침 0.3 미만 0.655)과 **짧은 구어**(0.760)가 가장 약하다.
- **시점 문항은 여전히 0점이다**(현행만 색인). 7장에서 다룬다.

4장에서는 질의 재작성, 재정렬 같은 처방으로 이 셋 중 앞의 둘을 다룬다.

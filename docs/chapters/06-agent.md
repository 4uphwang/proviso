# 6장. 참조·위임을 못 따라간다: 고정 파이프라인과 도구 쓰는 에이전트

## 문제

5장은 검색 상위 5개 조문을 조문마다 앞 3,000자씩 잘라 주고 답하게 했다. 채택한 거절 설정에서 이런 문제가 남았다(dev / test).

| 문제 | dev | test |
|---|---:|---:|
| 정답 조문을 모두 받음: 참조 문항(cross_ref) | 0.857 | 0.857 |
| 정답 조문을 모두 받음: 두 조문 문항(multi) | 0.75 | 0.80 |
| 정의 문항: 정답 조문을 받았는데 3,000자 뒤에서 잘려 답이 빠짐 | 답이 자료에 있음 0.571 | 0.478 |
| 정의 문항 핵심어 포함률 | 0.286 | 0.348 |
| 참조 문항 인용 재현율 | 0.50 | 0.482 |

법 조문의 "대통령령으로 정하는"은 시행령 조문이 정하고, 정의 조항(제2조)은 수십 개 호가 이어진다. 검색 한 번으로 5개를 고르면 이어진 조문을 놓치고, 긴 조문은 앞부분만 보인다.

## 처방: 자료를 누가 고르나

계획서대로 두 방식을 나눠 쟀다. **작은 모델은 도구 고르기에서 먼저 무너지고 답 쓰기는 버틸 수 있어서**, 둘을 나눠야 어디가 병목인지 보인다.

- **고정 파이프라인**: 코드가 검색하고, 긴 조문을 줄이고, 이어진 조문을 붙인다. 모델은 답만 쓴다.
- **에이전트**: 모델이 도구 4개를 골라 부르고, 결과를 읽고, 답한다. 루프는 프레임워크 없이 직접 짰다([`agent/loop.py`](../../src/proviso/agent/loop.py)).

### 도구 4개

| 도구 | 하는 일 |
|---|---|
| `search(query)` | 4장 R1 검색(RRF + 재정렬) 상위 5개 조문. 조문마다 질문과 겹치는 줄을 골라 1,000자까지 |
| `get_article(law, article)` | 조문 하나의 본문(4,000자까지)과, 그 조문과 이어진 조문 목록 |
| `follow_reference(law, article)` | 이어진 조문(위임받은 시행령, 위임한 법, 본문이 가리키는 조문) 4개의 본문 |
| `define_term(term, law?)` | "○○"이란 … 형태로 용어를 정의한 줄과 그에 딸린 호·목 |

- 이어진 조문은 [그래프 스키마](../graph-schema.md)의 위임·참조 관계다(4장에서 순위 점수로는 쓰지 않기로 한 것).
- 도구 결과에 본문이 나온 조문만 인용 근거로 친다. 이름만 나온 조문을 인용하면 환각 인용이다.
- 도구 오류(없는 법, 없는 조)는 예외가 아니라 글로 돌려준다. 같은 호출을 되풀이하면 막는다.
- 멈춤 조건: 도구 6턴, 호출 8번, 자료가 약 11,000토큰을 넘으면 도구 없이 지금까지 본 자료로 답하게 한다.

### 설정

모든 설정에 같은 답변 모델(로컬 `qwen3.5:4b`, temperature 0, 반복 억제 0, 답 500토큰까지)과 5장의 인용·거절 지시문을 쓴다. 비용은 0원이다.

| | 설정 | 자료 |
|---|---|---|
| | **fixed** (5장 그대로) | R1 상위 5개, 조문마다 앞 3,000자 |
| 고정 | focus | 3,000자를 넘는 조문은 앞부분 대신 질문과 겹치는 항·호를 골라 3,000자 |
| 고정 | follow | fixed + 상위 3개 조문과 이어진 조문 중 재정렬 점수 상위 3개(조문마다 1,500자) |
| 고정 | focus_follow | 둘 다 |
| 에이전트 | agent | 모델이 처음부터 도구를 고른다 |
| 에이전트 | agent_links | agent + 검색 결과마다 이어진 조문 이름을 보여 준다 |
| 에이전트 | **agent_seed** | 코드가 질문 그대로 한 번 검색해 결과를 먼저 주고, 그다음부터 모델이 도구를 고른다 |
| 대조 | short, short_follow | 도구 없이 조문을 검색 도구와 같은 1,000자로 줄인 것(+ follow) |

agent_links는 dev 12문항 시험에서 에이전트가 12문항 중 11문항을 검색 한 번으로 끝내 더했다. short와 short_follow는 dev 결과를 본 뒤 더한 대조 설정이다. agent_seed가 도구를 거의 더 쓰지 않았는데 점수가 올라서, **짧은 자료 덕인지** 가르려고 넣었다.

### 새 지표

| 지표 | 뜻 |
|---|---|
| 정답 조문을 모두 봄 | 답하기 전에 모델이 본 자료(고정: 준 자료, 에이전트: 도구 결과)에 정답 조문이 모두 있다 |
| 답이 자료에 있음 | 정답 조문이 하나라도 있고, 핵심어가 모두 자료 글에 있다 |

둘 다 답할 수 있고 시점이 아닌 문항(dev 56, test 106)만 센다.

## 무엇이 효과를 냈나

**1. 모델은 도구를 거의 쓰지 않았다.** test에서 agent_seed는 171문항 중 168문항에서 코드가 해 준 첫 검색 말고 도구를 더 부르지 않았다. 참조 따라가기는 한 번 썼다. agent도 171문항 중 141문항이 도구 한 번, 24문항이 도구 없음이었다. **이번 결과는 "도구를 골라 쓰는 에이전트"의 효과가 아니다.** 4B 모델은 도구 고르기를 거의 하지 않았다.

**2. 이어진 조문은 코드가 따라가야 보였다.** 정답 조문을 모두 본 비율을 올린 것은 코드가 이어진 조문을 붙인 focus_follow뿐이다(참조·두 조문 문항 0.833 → 0.958). dev에서 agent_seed가 참조·두 조문 정답을 다 못 본 5문항 중 3문항은 빠진 조문이 이미 본 조문과 바로 이어져 있었다. 모델이 `follow_reference`를 불렀다면 볼 수 있었다.

**3. 그런데 답은 agent_seed가 더 좋았다.** agent_seed와 short는 같은 조문을 거의 같은 길이로 본다(정답 조문을 모두 봄, 답이 자료에 있음 모두 차이 0). 그래도 인용 재현율 +0.137, 핵심어 포함률 +0.149로 갈렸다. 둘의 차이는 지시문의 자리(시스템 메시지 + 질문 먼저, 자료는 도구 결과로)와 도구 목록이 있다는 것, 그리고 **답 길이**다. agent_seed의 답은 평균 436자로 short(256자)의 1.7배이고, 조문을 더 많이 인용한다(인용 정밀도는 −0.079). **길게 쓴 답은 핵심어를 우연히 담을 가능성도 높다.** 셋 중 어느 것이 얼마나 기여했는지는 나눠 재지 않았다.

**4. 짧은 자료는 그 자체로 조금 도움이 됐다.** fixed → short는 인용 재현율 +0.118, 정밀도 +0.105로 구간이 0을 벗어났고, 핵심어 포함률(+0.062)은 0을 포함한다. 긴 조문의 앞부분 대신 질문과 겹치는 줄을 보여 준 focus도 비슷하다.

## 답을 직접 읽어 본 것

**핵심어가 달라진 문항.** test에서 short와 agent_seed의 핵심어 점수가 다른 문항은 34개(agent_seed가 높음 25, 낮음 9)다. 오른 25문항 중 무작위 8문항을 읽었다.

- 실제로 나아진 답 4개. a078(공개매수 공고에 적을 것)에서 short는 신고서 기재사항을 답했고 agent_seed는 공고 내용 9가지를 옮겼다. a133에서 short는 다른 조문으로 답했다. a139, a163도 근거 호를 직접 옮겼다.
- 같은 내용을 다르게 쓴 것 3개(a098, a166, a147). 핵심어 하나가 표현에 따라 맞거나 틀렸다.
- **뜻이 뒤집혔는데 점수가 오른 것 1개.** a214에서 agent_seed는 결손처분을 "할 수 **없는** 특별한 사유"라고 쓰고 할 수 있는 사유를 나열했다. 핵심어(면책된 경우, 환수가 불가능)가 다 있어 만점이다. dev a011도 같았다(제외 종목을 "거래할 수 있는 종목"이라고 씀).

**채점 오류 하나를 고쳤다.** 내려간 문항을 읽다가 `**6 개월 이내**`처럼 굵은 글씨 표시가 핵심어 사이에 끼면 맞춘 답도 못 찾는 것을 발견했다. 이제 `*`, `_`, `` ` ``를 지우고 맞춘다. 모든 설정에 똑같이 적용했고, 위 표는 모두 고친 채점기의 값이다. 고치기 전 test 핵심어 포함률은 agent_seed 0.827, agent 0.726, follow 계열은 그대로였다(dev의 설정 선택은 바뀌지 않는다). 5장 값도 자유 답변 0.654 → 0.678, 인용 형식 0.630 → 0.649로 바뀌고, 채택한 거절 설정(0.630)은 그대로다.

**답할 수 없는 질문.** agent_seed는 33문항 중 10문항에 답했다. fixed도 그중 6문항에 답했다. 새로 답한 것은 a228(의심거래보고 과태료: 수집하지 않은 특정금융정보법 질문인데 자본시장법으로 답함), a231(이사 선임 결의: 상법 질문인데 자본시장법 조문으로 답함), a246(약관 변경 공지 적법성: 개인 사안), a252(승소 가능성: 개인 사안)다. 남은 환각 인용 하나(a230)도 여기서 나왔다. 수집하지 않은 가상자산이용자보호법의 "제3조"를 썼다.

**지시문을 그대로 옮긴 거절**은 agent_seed test에 5개(a227, a240, a243, a263, a265) 있다. 5장 거절 설정은 6개였다.

**시점 문항은 더 나빠졌다.** 시점 문항 32개 중 fixed는 11개를 거절했지만 agent_seed는 4개만 거절했다. 나머지는 현행 조문으로 옛날 질문에 답했다. 답을 길고 자신 있게 쓰는 만큼, 옛날 질문에도 지금 규정으로 답한다. 7장의 문제다.

**dev에서 본 에이전트의 환각 인용은 test에서 재현되지 않았다.** dev agent는 도구 없이 답한 13문항에서 환각 인용 4개가 나왔지만, test agent가 도구 없이 답한 24문항은 22개가 답할 수 없는 질문이었고 23개를 거절했다. test agent의 환각 인용(0.029)은 fixed(0.023)와 구간이 겹친다.

## 지연과 토큰

| | 문항당 p50 | 모델 입력 토큰(평균) |
|---|---:|---:|
| fixed | 14.7 s | — |
| focus_follow | 30.2 s | — |
| agent_seed | 25.9 s | 3,560 |
| agent | 27.1 s | 4,055 |

- 시간은 답변 모델 시간 + 검색 시간이다. 검색은 파일에 저장한 결과를 다시 써서, 처음 검색할 때의 값을 더했다.
- agent_seed가 fixed보다 느린 것은 답이 길어서다. focus_follow는 자료가 1.4배 길어서 느리다.
- 로컬 모델이라 비용은 0원이다. 토큰은 Ollama가 돌려준 값이다.

## 질문 하나 답하고 기록 남기기

`proviso agent ask "<질문>"`은 agent_seed로 답하고, 자료에서 확인되지 않은 인용을 표시하고, 고지를 붙인다. 요청마다 단계(검색, 도구, LLM 호출)를 DB의 `traces`·`spans` 표와 `runs/traces/<날짜>.jsonl`에 남긴다. 도구 단계에는 본문 대신 보인 조문과 글자 수만 남긴다.

```text
$ proviso agent ask "온라인소액투자중개 등록하려면 자기자본이 얼마 필요한가요?"
온라인소액투자중개업자가 되고자 하는 자는 **5억원 이상**으로서 대통령령으로 정하는 금액 이상의 자기자본을 갖출 것을 요건으로 합니다.
[자본시장과 금융투자업에 관한 법률 제117조의4]
[자본시장과 금융투자업에 관한 법률 시행령 제118조의4]

※ 이 답변은 법률 자문이 아니며, 원문과 전문가의 확인이 필요합니다.
기록: proviso trace 4f7a91ad

$ proviso trace 4f7a91ad
| # | 단계 | 초 | 토큰 | 내용 |
|---:|---|---:|---:|---|
| 1 | tool:search | 28.8 | - | {"query": "온라인소액투자중개 등록하려면 …"} → 자본시장법 제117조의4, 자본시장법 시행령 제118조의17, … |
| 2 | llm:chat | 14.7 | 4021+80 | 답 |
```

첫 검색 28.8초 중 대부분은 임베딩·재정렬 모델을 올리는 시간이다. 이 답은 시행령 제118조의4가 정한 금액을 옮기지 않고 법 조문의 "5억원 이상"만 말한다. 계획서의 OpenTelemetry 내보내기는 아직 하지 않았다.

## 결과대로 기록한 것

- **도구를 골라 쓰는 에이전트(agent)는 고정 파이프라인보다 정답 조문을 덜 봤다**(−0.123). 검색을 건너뛰거나 한 번만 했다.
- **이어진 조문 이름을 보여 줘도(agent_links)** 모델은 참조 따라가기를 87문항 중 11문항에서만 썼고 점수는 오르지 않았다.
- 채택한 agent_seed의 좋은 점수는 도구 사용이 아니라 **대화 형식과 긴 답**에서 왔다. 둘을 나눠 재지 않았다.
- 정답 조문을 더 보여 준 focus_follow는 핵심어 포함률을 fixed보다 올렸지만(+0.096), agent_seed보다는 낮다.

## 한계

- 4B 로컬 모델 하나의 결과다. 도구를 쓰지 않는 것이 모델 크기 탓인지는 9장(모델 비교)에서 본다.
- 핵심어 포함률은 뜻이 뒤집힌 답도 맞다고 센다(a214, a011). 답이 길수록 유리하다. 충실도 판정은 아직 없다.
- 평가셋 정답의 사람 검수는 아직 하지 않았다(5장 한계와 같다).
- agent_seed와 focus_follow를 합친 설정(코드가 이어진 조문까지 붙여 주고 대화 형식으로 답하게)은 재지 않았다.
- 시점 문항은 현행 조문으로 답한다(7장).

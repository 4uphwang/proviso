# 9장. 얼마나 싼 모델에서 되나: 답변 모델 비교

## 문제

6~8장은 모두 로컬 `qwen3.5:4b` 하나로 쟀다. 그 결과에는 4B의 한계로 보이는 것이 섞여 있었다.

- 도구를 거의 쓰지 않았다(test 171문항 중 168문항이 코드가 해 준 첫 검색만 썼다).
- 정답 조문을 더 보여 주면 오히려 핵심어가 줄었다(6장 이어진 조문, 8장 조문 14개).
- 답할 수 없는 질문 33개 중 10개에 답했다(거절 정확도 0.697).

비싼 모델이 잘하는 것은 당연하다. 이 장의 질문은 **얼마나 싼 모델에서 이 설계가 제대로 돌아가는가**다.

## 처방: 모델만 바꾼다

7장 agent_asof를 그대로 쓴다(같은 검색, 같은 도구 4개, 같은 시스템 메시지, 첫 검색은 코드가, 조문 5개). 답변 모델만 바꾼다.

- 로컬(Ollama, 0원): `qwen3.5:4b`, `qwen3.5:9b`
- API(오픈라우터, OpenAI 호환): 도구 호출을 지원하는 싼 모델 중에서 골랐다. Upstage Solar mini4(한국어 모델, 계획서 필수), Z.ai GLM-5.3 Flash(가장 싼 축), DeepSeek V4 Flash, OpenAI gpt-oss-20b(로컬에도 있는 모델), Anthropic Claude Haiku 5.5(성능 좋은 쪽 기준점)
- 추론(thinking)은 끈다. gpt-oss-20b와 GLM은 끌 수 없어 가장 낮은 단계(`low`)로 돌렸다.
- API 연결은 `openrouter:<모델 id>[@추론 단계]`로 부른다(`agent/loop.py` OpenAIChat). 키는 요청 헤더로만 보내고 저장하는 파일(응답, 결과, 기록)에 넣지 않는다. 오류 글에 섞여 나와도 지운다.

### 재다가 고친 것 세 가지

**1. 대화 길이 한도.** 6장에서 4B의 문맥 창(16K)에 맞춰 대화가 11,000토큰을 넘으면 도구를 그만 쓰고 답하게 했다. 도구를 많이 쓰는 DeepSeek는 dev 87문항 중 13문항이 여기서 멈췄고, 그중 3개는 시행령을 마저 찾지 못해 거절했다. 64,000토큰으로 올려 dev를 다시 돌렸더니 멈춘 문항은 0개, 과잉 거절은 2개에서 1개가 됐지만 핵심어 포함률(0.922)은 같았다. **11,000을 그대로 둔다**(`--token-limit`으로 바꿀 수 있다).

**2. 답 길이 상한.** 5장에서 4B가 같은 말을 끝없이 되풀이하는 것을 끊으려고 답을 500토큰으로 막았다. 4B는 거의 걸리지 않았지만(5문항), API 모델은 답을 길게 써서 많이 잘렸다(dev 87문항 중 Haiku 59, DeepSeek 41, GLM 24, gpt-oss 15, Solar 13). 잘린 답은 문장 중간에서 끊겨 근거나 마지막 항목이 빠진다. **API 모델은 1,500토큰으로 올렸다**(`--max-tokens`). 1,500에 닿은 답은 dev에서 모델마다 0~3개다. 로컬 모델은 500 그대로다.

**3. 같은 입력에도 답이 달라진다.** temperature 0인데도 API 모델은 다시 돌리면 답이 달랐다. 500에서 잘리지 않은 문항끼리 두 번 돌린 답을 비교하면 완전히 같은 답은 Solar 72개 중 0개, DeepSeek 44개 중 3개, GLM 63개 중 10개, Haiku 28개 중 8개였다. 부르는 도구와 순서도 달라졌다. 그래서 Solar를 한 번 돌린 dev 핵심어 포함률이 0.980에서 0.922로 바뀌었다. **API 모델은 dev를 3회 돌려 평균과 범위를 본다**(`--repeat`, 반복 번호는 응답 저장 이름에만 쓴다). 로컬 모델은 seed를 고정해 매번 같다.

**Solar는 답할 수 없는 질문 33개 중 17개에 답했다.** 4b(10개)보다 많다. 모두 개인 사안 판단("판매 직원을 상대로 소송하면 이길 수 있을까요", "정보 유출 위자료 얼마")이거나 투자 조언("수익률 좋은 채권 추천", "리츠 vs 예금")이다. DeepSeek는 3개, GLM은 4개에 답했다. dev에서는 답할 수 없는 문항이 15개뿐이라 이 차이가 보이지 않았다.

**도구는 모델이 커야 쓴다.** 첫 검색 외에 도구를 쓴 문항이 4b는 test 171개 중 3개였고, DeepSeek는 112개였다. 참조·두 조문 문항에서 정답 조문을 모두 본 비율은 4b 0.833, DeepSeek 0.979다. 6장에서 4B로는 보지 못한 "도구로 참조를 따라가는 에이전트"가 이 정도 모델에서는 돌아간다.

## 결과대로 기록한 것

- **질문 하나에 1센트도 안 드는 모델로 이 설계가 제대로 돌아간다.** DeepSeek V4 Flash는 test 171문항에 $0.176(문항당 약 $0.001)으로, 핵심어 포함률, 인용 재현율, 거절 정확도에서 모두 4b보다 높았고 구간이 0을 벗어났다. 문항당 p50 13초로 로컬 4b(25초)보다 빠르다.
- **가장 싼 Solar mini4는 근거는 좋지만 거절을 못 한다.** 법령 자문 서비스에서 개인 사안과 투자 조언을 거절하지 못하는 것은 쓰지 못할 이유가 된다.
- 로컬 4b·9b는 0원이지만 한 단계 낮다. 9b로 키워도 나아지지 않았다.
- 6장의 "에이전트가 도구를 쓰지 않는다", 8장의 "자료가 길면 오히려 나빠진다"는 4B에서 본 것이다. 큰 모델에서도 그런지는 다시 재야 한다.

## 한계

- 채점은 8장의 핵심어 규칙(Sonnet 라벨과 κ 0.75)이다. 뜻이 뒤집힌 답을 맞다고 세는 문제는 모든 모델에 남아 있다. 답이 길수록 핵심어가 우연히 들어갈 가능성이 높다(API 모델의 답은 평균 400~740자, 4b는 400자).
- test는 모델마다 한 번이다. API 모델은 돌릴 때마다 답이 달라서 test 숫자도 ±0.05쯤 흔들릴 수 있다.
- 답할 수 없는 문항이 test 33개, dev 15개뿐이다.
- 모델 사이 비교는 로컬 500토큰, API 1,500토큰으로 답 상한이 다르다.
- 요금은 오픈라우터가 돌려준 값(2026년 11월)이고 바뀐다. 같은 모델도 어느 제공자로 보내느냐에 따라 값이 다를 수 있다.
- API로는 공개 법령 본문과 평가셋 질문만 보낸다. 개인 정보는 없다.
- 계획서의 GPT·Gemini 계열과 gemma4:12b는 돌리지 않았다. 임베딩 비교도 아직이다.

## 다시 돌리기

```bash
# .env에 OPENROUTER_API_KEY
proviso agent run --split dev --arms agent_asof --model qwen3.5:9b --retriever-config config/experiments/t1-asof.yaml
proviso agent run --split dev --arms agent_asof --model openrouter:upstage/solar-mini4 --max-tokens 1500 \
  --retriever-config config/experiments/t1-asof.yaml            # --repeat 1, --repeat 2로 반복
proviso agent run --split dev --arms agent_asof --model openrouter:z-ai/glm-5.3-flash@low --max-tokens 1500 …
proviso agent run --split test --arms agent_asof --model openrouter:deepseek/deepseek-v4-flash-0731 --max-tokens 1500 …
```

# 10장. 답하면 안 되는 질문에 답한다: 모델 앞의 거절 판별

## 문제

5장부터 거절은 모델에게 맡겼다. 시스템 메시지에 "개인 사안 판단, 투자 조언, 근거가 없는 질문은 정해진 문장으로 거절하라"고 적었을 뿐이다. 9장 test(답할 수 없는 질문 33개)에서 모델마다 결과가 크게 갈렸다.

| test | 거절 정확도 (n=33) | 답해 버린 질문 |
|---|---:|---:|
| qwen3.5 4b | 0.697 | 10 |
| Solar mini4 | **0.485** | **17** |
| GLM-5.3 Flash | 0.879 | 4 |
| DeepSeek V4 Flash | 0.909 | 3 |

답할 수 없는 질문은 평가셋에 세 종류가 16개씩 있다(dev 5개씩, test 11개씩).

- 수집하지 않은 법: "예금자보호 한도 얼마까지 됨?", "상속세 신고 기한"
- 개인 사안 판단: "제 경우 은행이 전액 물어줘야 하나요?", "판매 직원을 상대로 소송하면 이길 수 있을까요?"
- 투자 조언: "지금 삼성전자 사도 됨?", "수익률 좋은 채권 추천"

Solar가 답해 버린 17개는 모두 개인 사안이거나 투자 조언이었다. 이 두 종류는 법령을 몰라도 질문의 말투로 알아볼 수 있다.

## 처방: 모델을 부르기 전에 규칙으로 거른다

`answer/guard.py`의 `screen(question)`이 질문만 보고 판정한다. 걸리면 모델을 부르지 않고 정해진 문장으로 거절한다(`proviso agent run --guard`, `proviso agent ask`는 늘 켠다).

- **투자 조언**: "사도 됨", "들어가도", "추천해 줘", "어디에 투자", "전망", "오를까" 같은 매매·선택·전망 요청
- **개인 사안**: 1인칭("제", "내", "저희", "우리 회사", "남편")과 판단 요구("맞나요", "이길", "위자료", "책임 있", "위법한지")가 함께 있을 때
- 수집하지 않은 법령은 말투로 가를 수 없어 모델에게 남긴다.

규칙은 **dev 문항만 보고** 정했다. 과잉 차단은 정상 질문이 많은 곳에서 쟀다(에이전트 세트 dev 72개, 검색 세트 dev 300개). 처음 규칙은 검색 세트 dev에서 정상 질문 3개를 막았다("종목 **추천**을 하는 것도 투자자문업에 해당하나요?", "후보**추천**위원", "증권사 계열**사도 됨**?"). "추천"은 요청형일 때만, "사도 됨"은 띄어 쓴 독립 표현일 때만 걸리게 좁혀 0개로 만든 뒤 규칙을 고정했다.

### 판별기만 따로 잰 결과

| | dev | test |
|---|---:|---:|
| 개인 사안을 걸러 냄 | 5 / 5 | 10 / 11 |
| 투자 조언을 걸러 냄 | 5 / 5 | 11 / 11 |
| 에이전트 세트 정상 질문을 막음 | 0 / 72 | 0 / 138 |
| 검색 세트 정상 질문을 막음 | 0 / 300 | **2 / 700** |

- test에서 놓친 1개: "작년에 대출 거절당한 거 차별인지 판단 좀". 1인칭 표현이 없다.
- test에서 잘못 막은 2개: "OTP나 인증서를 … 빌려줬다가 돈이 빠져나가면 **제** 중대한 과실로 보나요?", "공개매수 기간 중에 공개매수자가 … 주식을 **사도 되나요**?". 둘 다 법을 묻는 질문인데 말투가 겹쳤다.

## 결과: 모델에 붙였을 때

판별기에 걸리지 않은 질문은 모델 입력이 전과 같아서 저장된 응답을 그대로 쓴다. 그래서 정상 질문의 답은 바뀌지 않고, 차이는 거절 정확도에만 난다.

| test | 거절 정확도 (n=33): 끔 → 켬 | 차이 [95% 구간] |
|---|---|---|
| qwen3.5 4b | 0.697 → **0.848** | +0.152 [+0.030, +0.273] |
| Solar mini4 | 0.485 → **0.848** | +0.364 [+0.212, +0.545] |
| GLM-5.3 Flash | 0.879 → **1.000** | +0.121 [+0.030, +0.242] |
| DeepSeek V4 Flash | 0.909 → **1.000** | +0.091 [0.000, +0.212] |

과잉 거절, 핵심어 포함률, 인용 재현율은 네 모델 모두 그대로다(에이전트 세트). dev에서도 같은 방향이다(4b 0.867 → 0.933, Solar 0.867 → 1.000, GLM·DeepSeek 0.933 → 1.000).

4b와 Solar에 남은 실패(test 5개씩)는 모두 수집하지 않은 법령 질문이다.

## 결과대로 기록한 것

- 비용 0원, 지연 0초인 규칙 하나로 네 모델의 거절 정확도가 모두 올랐다. 가장 싼 Solar mini4가 거절을 못 해서 후보에서 빠질 뻔한 문제가 메워졌다.
- 대가는 검색 세트 정상 질문 700개 중 2개를 잘못 막는 것이다. 막힌 질문도 "법령의 일반적인 내용은 물어 주시면 답하겠습니다"라는 안내를 받는다.
- 모델에게 지시로 맡기는 것보다 코드로 거르는 것이 확실했다. 7장의 연도 고지와 같은 교훈이다.

## 한계

- 규칙은 표현을 보고 정했다. 평가셋 질문은 Claude가 쓴 것이라 실제 사용자가 다르게 물으면 놓치거나 잘못 막을 수 있다.
- 답할 수 없는 질문이 dev 15개, test 33개뿐이다.
- 수집하지 않은 법령 질문은 다루지 않았다. 검색 점수나 법령 이름으로 가르는 방법을 생각해 볼 수 있다.
- 계획서의 가드레일 중 프롬프트 인젝션 차단과 개인정보 마스킹은 아직이다(11장).

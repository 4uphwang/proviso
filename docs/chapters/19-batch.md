# 19장. 기다려도 되는 일을 제값 주고 한다: 배치 API

## 문제

평가와 판정은 답을 바로 받을 필요가 없다. 그런데 지금은 모든 호출을 보통(동기) 호출로, 하나씩 정가에 보낸다. 계획서 E7은 이런 일을 배치 API로 보내 비용을 비교하는 것이다.

처음에는 할 수 없다고 봤다. Anthropic·OpenAI·Gemini 키가 없고, 지금까지 쓴 오픈라우터는 배치가 없다고 알고 있었다. 찾아보니 **오픈라우터가 2026년 9월 22일에 배치 API를 내놨다**(`POST /api/v1/batches`, 결과는 24시간 안, 가격은 모델별 배치 변형 가격). 가진 키로 쓸 수 있었다.

## 어디에 쓰나

- **에이전트 답변에는 맞지 않는다.** 모델 답을 받아야 다음 도구를 고르므로 한 질문 안의 호출을 한꺼번에 맡길 수 없다.
- **13장 충실도 판정이 맞다.** 답 하나에 한 번 부르면 끝나고, 결과를 바로 볼 필요가 없다.

오픈라우터 모델 목록(2026-11-25)의 배치 가격은 모델마다 할인 폭이 달랐다.

| 1M토큰당 | 보통 입력 / 출력 | 배치 입력 / 출력 |
|---|---|---|
| DeepSeek V4 Flash | $0.046 / $0.300 | $0.048 / $0.144 (입력은 오히려 조금 비싸고 출력만 절반) |
| GLM-5.3 Flash (13장 판정자) | $0.150 / $0.500 | $0.023 / $0.068 |
| Claude Haiku 5.5 | $0.100 / $0.500 | $0.050 / $0.250 |

## 처방

- `agent/batch.py`: 맡기기(`submit`) → 상태 보기(`wait`, 30초마다) → 결과를 `custom_id`로 맞추기. 요청 본문은 보통 호출과 같은 함수(`OpenAIChat.request_body`)로 만든다. 문서대로 `endpoint`·`model`을 `requests`보다 앞에 둔다.
- `eval/faith_run.py` `run_faith_batch`: 여러 실행의 답을 배치 하나로 판정하고, 결과를 보통 판정과 같은 모양으로 쓴다.
- 모의 서버 테스트(`tests/test_batch.py`): 결과 순서가 뒤섞여 와도 `custom_id`로 맞추기, 실패한 줄 남기기, 키가 오류 글에 안 나오기.

## 계획대로 안 된 것: GLM 배치는 실패했다

13장 판정자(GLM-5.3 Flash)로 test 답 553개를 배치 하나로 맡겼다. 오픈라우터는 받았지만(202) 곧 `failed`, "Failed to submit batch to provider."였다(공급자 Together). 요청 두 개짜리로 줄여 나눠 봤다.

| 2개짜리 시험 배치 | 결과 |
|---|---|
| GLM, 보통 요청 본문 그대로 | 실패(Together) |
| GLM, 추론 설정 뺌 | 실패(Together) |
| GLM, 메시지와 길이 제한만 | 실패(Together) |
| GLM, 모델 이름에 `:batch` | 실패(Together) |
| DeepSeek V4 Flash | 완료(DeepInfra), 419초 |
| Haiku 5.5 | 완료(Anthropic), 460초 |

요청 본문과 상관없이 GLM 배치만 공급자에 넘어가지 못했다. 다시 해 봐도 같았다. 실패한 배치에는 요금이 붙지 않았다.

또 하나: 맡긴 직후 상태를 물으면 404("not found")가 났다. 첫 몇 번의 404는 기다리도록 고쳤다.

## 바꾼 실험: DeepSeek로 같은 판정을 보통 호출과 배치로

GLM 대신 DeepSeek V4 Flash로, 13장에서 Sonnet 라벨을 붙인 60문항(dev 30, test 30)을 배치로 판정했다. 이 60문항은 13장에서 DeepSeek 보통 호출로도 판정해 두었으니, **같은 판정자·같은 입력**으로 보통 호출과 배치를 견줄 수 있다.

| 60문항 | 보통 호출 | 배치 |
|---|---:|---:|
| 비용 | $0.0505 | **$0.0230 (−54%)** |
| 걸린 시간 | 214초(하나씩 보낸 응답 시간 합) | 406초(맡긴 때부터 끝날 때까지) |
| 실패 | 0 | 0 |
| 공급자 | 7곳에 나뉨(CoreWeave, Cohere, Wafer, Nebius, DeepInfra 등) | DeepInfra 한 곳 |

| 판정 | dev 30 | test 30 |
|---|---|---|
| 보통 호출과 배치의 판정이 같음 | 28 | 24 |
| 라벨과 일치(κ): 보통 호출 | 23 (0.49) | 23 (0.43) |
| 라벨과 일치(κ): 배치 | 23 (0.48) | 21 (0.20) |

- **비용은 절반 아래가 됐다.** 판정은 입력이 대부분(입력 42만 토큰, 출력 2만 3천 토큰)인데 DeepSeek 배치는 입력 할인이 없어서, 할인은 거의 출력 쪽과 공급자 차이에서 왔다. 배치 출시를 다룬 글들은 오픈라우터가 배치를 가장 싼 공급자로 보낸다고 전한다(공식 문서에서는 확인하지 못했다).
- **더 빠르지는 않았다.** 하나씩 보내도 214초였던 일이 배치로는 406초 걸렸다. 배치는 빨리 받는 방법이 아니라 싸게 받는 방법이다. 맡겨 두고 다른 일을 할 수 있다는 점이 이득이다.
- **판정이 test에서 6개 달라졌다.** 9장에서 본 대로 API 답은 매번 다르고, 이번에는 공급자도 달랐다(보통 호출은 7곳, 배치는 한 곳). 라벨과의 κ가 0.43 → 0.20으로 떨어졌지만 30문항에서 2개 차이라 흔들림과 가를 수 없다. 원인을 가리려면 보통 호출도 DeepInfra로 고정해 다시 재야 하고, 하지 않았다.

## 결정

- **판정처럼 기다려도 되는 단일 호출은 배치로 보낼 수 있게 했다**(`run_faith_batch`). DeepSeek 기준 비용이 절반 아래다.
- 13장 판정자(GLM-5.3 Flash)는 지금 배치가 되지 않으므로 보통 호출을 쓴다. 배치가 되면 할인 폭이 가장 크다(입력 약 85%).
- 배치로 바꾸면 공급자가 바뀌어 판정이 달라질 수 있다. 판정자를 바꿀 때처럼 라벨과의 일치를 다시 확인하고 쓴다.

## 한계

- 60문항, 한 번씩만 쟀다. 판정 차이가 공급자 탓인지 매번 다른 답 탓인지 가르지 않았다.
- GLM 배치 실패 원인은 공급자(Together) 쪽으로 보이지만 확인할 방법이 없었다.
- 배치 가격은 2026-11-25 오픈라우터 모델 목록 값이다. 실제 청구는 배치의 `usage.cost`로 확인했다.
- 에이전트 답변(여러 번 오가는 호출)은 배치로 보내지 않았다.
- 이 장의 비용은 실패한 배치(0원), 시험 배치, 60문항 배치를 합쳐 약 0.03달러였다.

# 법적 검토 메모 (2026-11-20)

> 변호사 검토가 아니라 공개 자료를 바탕으로 정리한 위험 점검이다. 확신이 필요한 항목(특히 §5 재직 중 개발)은 근로계약서·취업규칙을 직접 확인한다.

## 요약
| 항목 | 위험 | 조치 |
|---|---|---|
| 1. 법령 데이터 수집·공개 | 낮음 | 공식 API만 사용, **출처(법제처 국가법령정보센터) 표기 필수**, 원문 변형 금지 |
| 2. 약관 PDF | 중간 | 원문을 저장소에 올리지 않음. 공정위 표준약관 우선, 사기업 약관은 URL·다운로드 스크립트만 |
| 3. 변호사법(비변호사 법률사무) | 낮음 | 무료·비영리·로컬 데모, 개별 사안 판단 거절, 고지문 |
| 4. 금융 규제(투자자문) | 낮음 | 투자 권유·종목 판단 질문 거절 |
| 5. 재직 중 개인 프로젝트 | **확인 필요** | 개인 시간·개인 장비·개인 계정, 회사 자료·수치 미사용, 계약서의 겸업·직무발명 조항 확인 |
| 6. 모델·API 라이선스 | 낮음 | 임베딩 3종 모두 MIT/Apache-2.0, API는 각 약관 범위 |
| 7. 개인정보 | 낮음 | 평가셋·트레이스에 실존 인물 정보 넣지 않음 |

## 1. 법령 데이터
국가법령정보센터 공동활용 이용안내(open.law.go.kr) 원문 기준:
- 법령정보는 공공데이터 정책에 따라 **영리 목적 이용을 포함해 자유롭게 활용**할 수 있다고 명시돼 있다. 법령 본문은 저작권법 제7조(보호받지 못하는 저작물)에도 해당한다.
- 다만 **형사처벌 대상**으로 두 가지를 명시한다:
  1. 법령정보를 위조·변조해 제공하는 행위
  2. **출처를 표기하지 않거나 법제처 이외의 기관으로 표기하는 행위**(저작권법 제137조·제138조)
- 모든 데이터 활용은 공동활용 신청·승인 뒤 가능하고, 운영 신청 시 활용사례 등록이 필요하다.
- law.go.kr의 robots.txt는 전체 허용이다. 그래도 수집은 **공식 Open API만** 쓴다(조사 단계에서 사이트 내부 엔드포인트를 몇 번 조회한 것은 분량 파악용이었고, 수집 코드에는 쓰지 않는다).

이 프로젝트에 주는 의미:
- README, CLI 답변, 데모 화면에 "출처: 법제처 국가법령정보센터" 표기
- 조문 본문은 받은 그대로 저장한다. 파싱·정규화는 별도 필드에 두고 원문 필드는 손대지 않는다.
- **부칙 보정은 원문 변경이 아니라 메타데이터(유효 기간) 추정**임을 데이터와 답변에 명시한다(`보정 출처` 필드, "시행일은 부칙을 근거로 추정" 표시). 그래야 "변조"로 오해받지 않는다.
- 공개 저장소에 수집한 원본 JSON을 커밋할 필요는 없다(재수집 스크립트로 충분). 평가셋에 들어가는 짧은 조문 인용은 문제없다.

## 2. 약관
- 사기업(증권사·핀테크)이 만든 약관은 법령과 달리 저작권 보호 대상일 수 있다. 공개돼 있다는 것과 재배포해도 된다는 것은 다르다.
- 공정거래위원회 **표준약관**은 국가가 업무상 작성한 공공저작물이라 저작권법 제24조의2에 따라 자유 이용 범위가 넓다(개별 공공누리 표시는 수집할 때 확인).

조치:
- 저장소에는 약관 원문(PDF, 추출 텍스트)을 **커밋하지 않는다**. `sources.yaml`에 URL만 두고 로컬에서 내려받는다.
- 데모·README 예시는 표준약관 위주로 쓴다. 사기업 약관은 답변에서 짧게 인용하는 수준(저작권법 제28조 인용)으로만 보여 준다.
- 회사 로고는 쓰지 않는다. 회사 이름은 출처 표기로만 쓴다.

## 3. 변호사법
- 변호사법 제109조는 변호사가 아닌 사람이 **금품·이익을 받거나 받기로 하고** 법률상담 등 법률사무를 처리하는 것을 금지한다.
- 이 프로젝트는 무료이고, 비영리이며, 로컬에서 도는 포트폴리오다. 일반에게 공개된 상담 서비스로 운영하지 않는다.

조치:
- 답변은 "조문이 무엇이라고 되어 있는가"에 한정한다. "제 경우 소송하면 이기나요" 같은 개별 사안 판단은 거절 유형으로 평가셋에 넣는다.
- 모든 답변에 "법률 자문이 아니며 원문과 전문가 확인 필요" 고지
- 공개 웹 데모를 열게 되면 그때 다시 검토(현재 계획엔 없음)

## 4. 금융 규제
- 자본시장법상 투자자문업은 금융투자상품의 가치나 투자 판단에 대한 조언을 업으로 하는 것이다. 법령 문구 설명은 해당하지 않는다.
- 조치: "이 종목 사도 되나요" 같은 투자 판단 질문은 거절. 평가셋 거절 유형에 포함.

## 5. 재직 중 개인 프로젝트 (확인 필요)
지금 재직 중이라 이 부분이 실제로 가장 신경 써야 할 곳이다.
- **겸업 금지**: 취업규칙·근로계약서에 겸업·외부 활동 조항이 있는지 확인. 무료 개인 프로젝트는 보통 문제가 안 되지만 조항 문구에 따라 다르다.
- **직무발명**(발명진흥법): 회사 업무 범위에 속하고 회사 자원으로 만든 발명은 회사가 권리를 주장할 수 있다. LLM 검색·평가는 현재 직무와 겹치므로 **개인 시간, 개인 장비, 개인 계정·API 키**로만 작업한다. 회사 노트북·회사 클라우드·회사 API 키는 쓰지 않는다.
- **영업비밀**(부정경쟁방지법): 하이브리드 검색, RRF, 평가셋으로 개선하는 방법은 공개된 일반 기법이라 문제없다. 하지만 회사 내부 데이터, 프롬프트, 평가 문항, **내부 성능 수치**, 내부 시스템 구조는 README·이력서·면접 자료에 쓰지 않는다. "이전 직장 경험"은 일반 수준(무엇을 했는지)으로만 쓰고, 이 프로젝트의 숫자는 이 프로젝트에서 잰 것만 쓴다.
- 커밋 시각이 근무 시간에 몰리지 않게 하는 것도 나중의 분쟁 예방에 도움이 된다.

## 6. 모델·API
- 임베딩 라이선스(Hugging Face 기준): bge-m3 MIT, KURE-v1 MIT, Qwen3-Embedding-0.6B Apache-2.0. 모두 상업·비상업 사용과 결과 공개에 문제없다. README에 라이선스를 적는다.
- LLM API(Claude, GPT, Gemini, Solar): 공개 법령을 입력으로 보내고 결과를 비교·공개하는 것은 일반적인 사용 범위다. 경쟁 모델 학습에 출력을 쓰는 것은 금지 조항이 흔하지만 이 프로젝트는 학습을 하지 않는다. 결과표에는 모델 버전과 측정 날짜를 적는다.
- 무료 등급 API는 입력이 품질 개선에 쓰일 수 있다. 공개 데이터만 보내므로 문제없지만 개인정보는 보내지 않는다.

## 7. 개인정보
- 평가 질문과 트레이스에 실존 인물의 이름, 계좌, 연락처를 넣지 않는다. 사례형 질문은 가상의 인물로 쓴다.

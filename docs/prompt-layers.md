# 에이전트 프롬프트의 층

에이전트가 모델에게 보내는 입력은 `src/proviso/agent/prompt.py`에서 이름 붙은 블록으로 조립한다. 블록마다 **바뀌는 때**로 층을 정하고, 모델 입력은 늘 고정 → 질문 → 호출 순서로 쌓는다.

| 층 | 바뀌는 때 | 블록 (넣은 장) | 메시지 자리 |
|---|---|---|---|
| **고정** | 프로그램이 바뀔 때만 | 도구 정의 `tools.SPECS` (6장) | `tools` |
| | | `role`: 역할과 수집한 법령 목록 (6장) | 시스템 메시지 |
| | | `tool_use`: 도구를 언제 쓰는가 (6장) | 〃 |
| | | `cite`: `[법령명 제N조]` 인용 형식, 본 조문만 인용 (5장) | 〃 |
| | | `refuse`: 근거가 없거나 개인 판단·투자 조언이면 정해진 문장으로 거절 (5장) | 〃 |
| **질문** | 질문마다 | `date_note`, `year_only`: 기준일과 그날 조문으로 답하라는 안내 (7장, 18장에서 질문 앞으로 옮김) | 첫 사용자 메시지 |
| | | 질문 | 〃 |
| **호출** | 모델 호출마다 | 첫 검색 결과(코드가 질문 그대로 검색), 도구 호출과 결과 | 그 뒤 메시지 |
| | | `finish`: 한도에 걸리면 "지금까지 본 자료로 답하라" (6장) | 마지막 사용자 메시지 |

## 지키는 규칙

- **고정 층에는 질문마다 바뀌는 값을 넣지 않는다.** 앞부분 캐시는 앞부분이 같아야 읽힌다(18장). 7장의 기준일 문구가 시스템 지시 안에 있어서 기준일 질문이 캐시를 못 읽었던 것을 18장에서 찾아 고쳤다. `tests/test_prompt.py`가 고정 블록에 `{laws}` 말고 채울 칸이 있거나 날짜·기준일 문구가 들어가면 실패한다. `{laws}`는 수집한 법령이 바뀔 때만 바뀐다.
- **층 순서를 지킨다.** 블록 목록이 고정 → 질문 → 호출 순서가 아니면 테스트가 실패한다.
- **프롬프트 버전을 남긴다.** `prompt_version()`은 도구 정의와 모든 블록의 틀을 해시한 앞 8자리다(지금 `40e5b67e`). 에이전트 평가 결과(`runs/*_agent-*.json`), 공격 평가 결과, `ask` 기록의 config에 들어간다. 블록 한 글자를 바꿔도 값이 바뀌므로, 결과 두 개가 같은 프롬프트로 쟀는지 이 값으로 가린다.

## 규칙은 프롬프트 밖에도 있다

모델에게 지시하는 것보다 코드가 확실했던 규칙(7·10·11장)은 프롬프트 층이 아니라 모델 앞뒤의 코드에 있다.

| 언제 | 무엇 | 어디 |
|---|---|---|
| 모델 전 | 개인정보 가리기, 지시 바꾸기·없는 조문·개인 사안·투자 조언 거르기 | `answer/pii.py`, `answer/guard.py` |
| 모델 전 | 질문에서 기준일 읽기, 그날 조문으로 도구 만들기 | `agent/run.py` `as_of_setup` |
| 모델 뒤 | 인용 검증(본 조문인가, 있는 조문인가), 시스템 지시문 유출 검사, 연도만 물은 질문의 고지 | `answer/cite.py`, `answer/guard.py`, `agent/run.py` |

## 블록으로 나눌 때 바뀐 것

없다. 나누기 전 문자열(커밋 4a36229)의 해시와 조립 결과가 같다는 것을 테스트로 고정했고, dev 20문항(기준일 문항 3개 포함)을 다시 돌려 저장된 모델 응답이 모두 그대로 쓰이고 답이 한 글자도 같음을 확인했다.

## 이 층 구조 밖의 프롬프트

- 5장 정해진 파이프라인(`answer/run.py`의 `BASE`·`CITE`·`REFUSE`). 에이전트의 `cite`·`refuse` 블록이 같은 문장을 가져다 쓴다.
- 판정자 프롬프트: 8장 핵심어 판정(`answer/judge_llm.py`), 13장 충실도 판정(`answer/faith.py`).
- 4장 질의 재작성·HyDE(`retrieve/query_llm.py`).

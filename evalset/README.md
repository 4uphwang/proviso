## 검색 세트(`retrieval.jsonl`)

정답 조문을 먼저 뽑고(`proviso.eval.targets`, 시드 고정) 그 조문을 보고 질문을 썼다. 작성 규칙은 [GUIDELINES.md](GUIDELINES.md).

| 유형 | 문항 | | 형태 | 문항 |
|---|---:|---|---|---:|
| 조문 찾기(별표 50 포함) | 726 | | 키워드형 | 300 |
| 위임 따라가기 | 100 | | 짧은 구어(오타 50 포함) | 349 |
| 시점 | 95 | | 완결 문장 | 351 |
| 정의 | 79 | | | |

- dev 300 / test 700(유형별 30%). 법 이름이 들어간 질문 약 28%.
- 시점 문항은 옛 본문에 지금과 다른 규칙(숫자·기간·주체·조건)이 있는 조문만 쓴다. 용어·조문 번호만 바뀐 개정은 제외해서 처음 몫 100개를 다 채우지 못했고, 빈 5자리는 조문 찾기로 채웠다.

**검수 경로**
1. Claude가 질문 작성, 자동 검사(조문 번호, 길이, 형태별 끝맺음, 연도, 단어 겹침)
2. 리뷰 에이전트가 정답 조문 전체 본문과 대조해 1,000문항 독립 검토 → 지적된 문항은 고치거나 대상 조문을 바꾸고, 바뀐 문항만 다시 검토(3차까지)
3. 사람이 표본과 바뀐 문항을 검수

`origin`: `human` = 사람이 검수(135: 처음 112, 2026-11-25 검수 시트에서 맞음 20, 라벨을 고친 3), `ai_verified` = 리뷰 에이전트 검토 통과(865).

## 에이전트 세트(`agent.jsonl`)

답변의 인용·거절·핵심어까지 채점하는 세트다. 검색 세트와 같이 정답 조문을 먼저 뽑고 그 조문을 보고 질문을 썼다.

| 유형 | dev | test | 합계 |
|---|---:|---:|---:|
| 조문 찾기 | 16 | 35 | 51 |
| 위임 따라가기 | 14 | 28 | 42 |
| 정의 | 14 | 23 | 37 |
| 두 조문을 함께 읽기 | 12 | 20 | 32 |
| 시점 | 16 | 32 | 48 |
| 답할 수 없는 질문 | 15 | 33 | 48 |
| 합계 | 87 | 171 | 258 |

- 계획은 300문항이었다. 약관은 수집한 문서가 없어 30문항을 뺐고, 남은 270문항 중 12문항은 조문이 준용·위임 한 줄뿐이거나 두 조문이 서로 무관해 질문을 만들 수 없었다.
- `must_include`: 맞는 답이라면 들어갈 짧은 핵심어. 정답 조문 본문에 글자 그대로 있는지 검사했다.
- 답할 수 없는 질문: 수집하지 않은 법, 개인 사안 판단, 투자 조언 등. 정답 조문이 없고 거절해야 맞다.

**검수 경로와 한계**
1. Claude가 질문과 핵심어 작성, 자동 검사
2. 로컬 모델(gpt-oss 20B 양자화)이 후보 조문 중 정답 조문을 고르는지 확인(`proviso.eval.verify_agent`). 결과는 [5장](../docs/chapters/05-grounding.md#한계)
3. 사람 검수는 검수 시트의 무작위 표본 15문항뿐이다(모두 맞음, `origin: human`). 나머지 243문항은 `auto`다

## 후속 질문 세트(`followup.jsonl`)

첫 턴은 에이전트 세트 문항과 DeepSeek의 실제 답(인용 조문 포함), 두 번째 턴은 앞 대화에 기대는 질문이다. 정답 조문은 법령 그래프(위임, 벌칙 조문의 참조, 조문 연혁)에서 먼저 고르고, Claude가 조문을 읽고 질문을 썼다. 후보 172개 중 89개는 첫 질문과 동떨어졌거나 첫 답이 이미 다 말해서 뺐다. 형식: `{"id", "split", "kind", "turns": [{"question", "answer", "cites", "from"}], "question", "gold", "must_include", "origin", "notes"}`.

## 사람 검수 시트

`proviso.eval.review.build`가 사람이 볼 문항을 고른다: 검색·에이전트 세트에서 각각 무작위 30문항(라벨 오류율 추정용)과, 기본 설정이 틀린 의심 문항(검색 10위 밖 45, 에이전트 핵심어 빠짐·거절 21). 이미 사람이 본(`human`) 문항은 뺀다. 판정(맞음·틀림·애매, 메모)을 `review.apply`로 되돌리면 맞음은 `origin: human`이 되고, 틀림·애매는 `notes`에 메모가 붙는다(라벨 수정은 메모를 보고 따로 한다).

사람이 다 보기에는 많아서 두 번째 판(2026-11-25)에서 줄였다.
- 무작위 표본: 세트마다 15문항, 모두 30문항. 오류율은 이 표본에서만 센다. 30문항이면 신뢰구간이 넓다.
- 의심 문항 66개: 다른 계열 모델(GLM-5.3 Flash)이 먼저 라벨을 판정했다(`review.triage`). 라벨은 Claude가, 답은 DeepSeek가 만들었으므로 둘과 다른 모델을 골랐다.
  - 결과는 맞음 58, 틀림 5, 애매 3이었다. 틀림·애매로 나온 8문항(모두 검색 세트)만 사람이 본다.
  - 판정 결과는 `data/evalset_work/review_triage.json`에 있고, 비용은 $0.023이었다.
- 한계: 모델이 맞음이라고 한 58문항은 사람이 보지 않았다. 그중에 틀린 라벨이 남아 있을 수 있다.

검수 결과(2026-11-25)
- 무작위 30문항: 모두 맞음. 라벨 오류율은 0/30이고, 95% 상한은 약 10%다.
- 모델이 고른 8문항: 라벨이 실제로 틀린 것은 3개다. 나머지 5개는 모델이 조문을 잘못 읽었다(누가 사고 파는지 헷갈림, 대출모집인 근거법 착각 등).
  - r0815: 답이 시행령 제27조②7호에 있는데 법 제31조만 정답이었다.
  - r0087: 소비자보호 위반은 과태료(제69조)인데 양벌규정(제68조)만 정답이었다.
  - r0521: 질문 용어가 '일반투자자'인데 자본시장법 쪽 조문이 없었다.
  - 세 문항 모두 정답 조문을 고치고 `origin: human`으로 바꿨다. `proviso gate check` 기준 recall@10은 0.8066에서 0.8077이 됐다.

## 평가 실행

```bash
proviso eval --config config/experiments/<이름>.yaml            # dev(설정 고르기)
proviso eval --config config/experiments/<이름>.yaml --split test  # 보고용
proviso compare runs/<A>.json runs/<B>.json --out runs/<A>_vs_<B>.md
```

- 채점: 검색 결과를 조문 버전 단위로 묶은 뒤 주 정답(gold[0])의 순위로 recall@1·5·10·20, MRR@10을 낸다. 시점 문항은 그 시점 버전이어야, 나머지는 실행일에 유효한 버전이어야 정답이다. 위임 문항은 법 조문까지 함께 찾았는지도 따로 센다. 규칙은 `src/proviso/eval/metrics.py` 머리말.
- 칸별: 유형, 질문 형태, 오타, 법령명 포함, 법령, 단어 겹침 구간.
- 신뢰구간: 문항 단위 부트스트랩 1,000회(95%). 비교는 짝지은 부트스트랩으로 B − A 구간이 0을 넘는지 본다.
- 결과 파일(`runs/*.json`, git 제외)에는 설정, 검색기 설명, 데이터 스냅샷 ID, 평가셋 해시, 커밋, 문항별 순위·지연이 들어간다. `compare`는 평가셋·split·문항이 다르면 거부하고, 스냅샷이 다르면 `--allow-snapshot-mismatch` 없이는 거부한다.
- `random` 검색기(우연 수준): test recall@10 0.009, recall@20 0.017.
- CI 점수 검사(`proviso gate check`, `tests/test_gate.py`): 모델·DB 없이 형태소 BM25 + 약칭 확장으로 시점 문항을 뺀 905문항을 돌려, recall@10이 `ci_gate.json`의 기준값 − 허용폭(0.01) 아래면 실패한다. 말뭉치는 `tests/fixtures/corpus.jsonl.gz`(현행 조문, 출처 법제처). 데이터를 다시 뽑으면 `proviso gate export --as-of <날짜>` 후 `proviso gate check --update`.
